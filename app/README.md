# 사파리-어트랙션 앱 (조각 1 · 3 · 4)

사파리 옆에 붙는 Claude 옆 창 앱. MCP 서버(`src/` · `plugin/` · `mcpb/`)와는 따로다.

- `AppCore/` — 순수 로직 Swift 패키지(`AppCore` 라이브러리 + `AppCoreTests`). Apple 프레임워크만 쓴다.
- `SafariAttractionApp/` — 앱 실행 파일 패키지(`SafariAttractionApp`, `AppCore` 를 경로로 참조). 메뉴 막대 아이콘만 있는 앱(Dock 아이콘 없음).
- `extension/` — 사파리 확장 씨앗(`manifest.json` · `background.js`), 조각 2 에서 채운다.

## 빌드 · 시험 · 실행 (Xcode 없이)

```sh
app/scripts/build.sh   # swift build -c release → app/.build/SafariAttractionApp.app 조립 + ad-hoc 서명
app/scripts/test.sh    # AppCore 시험(swift test)
open -g app/.build/SafariAttractionApp.app                     # 앞으로 안 나오게 띄우기
osascript -e 'quit app id "com.gulzzaang.SafariAttractionApp"'  # 끄기
```

`app/.build/` 는 git 에 올리지 않는다.

### 개발용 주소 (`DEV=1` 빌드에서만)

`safariattraction://toggle`(옆 창 열기 · 닫기) · `safariattraction://ask?model=claude&q=…&web=1&page=1[&open=1]`(질문을 친 것처럼 보내고, 끝나면 `~/Library/Application Support/SafariAttractionApp/dev-last.json` 에 결과를 적는다) 는 **`DEV=1 app/scripts/build.sh` 로 만든 빌드에서만** 있다. 평소 빌드(`app/scripts/build.sh`)에는 이 주소 등록도, 받는 코드도 없다. DEV 빌드에서도 `defaults write com.gulzzaang.SafariAttractionApp DevHooks -int 1` 을 해 둔 때만 반응한다(앱 자신의 설정 도메인 하나만 읽는다 — 전역 설정 · 실행 인자는 읽지 않는다).

## 조각 2(사파리 확장) 전에

사파리 확장 대상은 Xcode 도구(`safari-web-extension-converter` · `xcodebuild`)가 필요하다. 이 맥은 Xcode 첫 실행 구성요소가 안 깔려 있어서, 먼저 터미널에서 `sudo xcodebuild -runFirstLaunch` 를 한 번 실행하거나 Xcode 를 한 번 열어 설치를 마쳐야 한다.

## 쓰는 법 (시험판 — 이 맥에서만)

> **아직 앱을 띄워 보는 확인은 안 했다.** 코드 · 단위 시험(685개) · 빌드까지만 끝났다. 옆 창 위치 · 따라가기 · 클로드 답 · 웹 검색 · 「이 페이지 함께」 · 허락 창은 박정욱이 맥 앞에 있을 때 확인한다. **「일 맡기기」(작업 목록 카드 · 동작 카드 · 코드 카드 · 사이트 허락 · 카드가 기다리는 동안 옆 창이 안 숨는 것 · 메뉴 막대 「기다림」 아이콘 · 앱 안에 넣은 서버 묶음으로 실제 클로드 · 사파리를 움직이는 것)도 마찬가지로 화면을 한 번도 띄워 보지 못했다** — 서버 · 관문 · 뷰모델은 시험으로 확인했지만 화면과 실제 연결은 아직이다. 아래는 그렇게 동작하도록 만든 내용이다.


- **열기 · 닫기**: **⌘E — 사파리(또는 이 앱)가 맨 앞일 때만**(어사이드와 같은 방식. 앱이 맨 앞 앱을 보다가 사파리가 앞이면 단축키를 걸고, 다른 앱이 앞이면 풀어서 그 앱의 ⌘E 를 빼앗지 않는다. 사파리의 ⌘E 「선택한 글로 찾기」 는 이 앱이 떠 있는 동안 가려진다). 어느 앱이 앞이어도 되는 전역 예비로 ⌥⇧S(Option+Shift+S)도 남겼다. 메뉴 막대 아이콘으로도 열린다. 옆 창은 사파리 앞 창 오른쪽 바깥에 붙고(자리가 없으면 안쪽에 겹침), 사파리 창이 움직이면 따라간다. 사파리가 뒤로 가면 숨는다 — 「고정」 을 켜면 안 숨는다.
- **CLI · 모델**: 클로드(`claude -p`) · 제미나이(`agy -p`) · ChatGPT(`codex exec`) · opencode(`opencode run`) 넷을 고른다(계획 10). 옆 창 위쪽에서 CLI 를, 입력 칸 아래에서 모델을 고른다. 모델 목록: 클로드는 고정(Sonnet · Opus · Haiku · Fable, 기본 Sonnet) · 제미나이는 `agy models`(기본 `gemini-3.8-flash-medium`, 없으면 첫 것) · codex 는 로그인 뒤 `codex debug models` 에서 보이는 것만(기본 첫 것) · opencode 는 `opencode models`(기본은 `-free` 로 끝나는 첫 것). 못 불렀으면 「모델 목록을 못 불러왔어요 — 로그인했는지, codex 가 최신인지 확인해 주세요(지금은 기본 모델로 물어요)」(CLI 마다 문구가 조금 다름). 고른 CLI · 모델은 `settings.json` 에 남는다. 로그인이 안 된 걸 아는 CLI 는 흐리게 보이고 누르면 「설정에서 로그인」. 로그인 상태는 **종료 코드 1 일 때만** 「안 됨」이고, 그 밖의 0 아닌 종료(시간 초과 포함)는 「알 수 없음 — 종료 코드 N …」 이라 칩을 막지 않는다. 마지막 답에 쓴 양(토큰 수)이 입력 칸 아래에 작게 보인다. **입력 칸 아래 「남은 양 · 5시간 23% 사용 · 주간 48%」 한 줄**은 고른 CLI 의 값이고(제미나이는 고른 모델 묶음 — 제미나이 / 클로드 · GPT — 의 창), 못 읽으면 숨긴다. 옆 창을 열 때 **고른 CLI 만**, 5분에 한 번까지 읽고(메인 밖 · 20초 상한), 클로드는 답에 딸려 오는 `rate_limit_event`(한도 창이 든 경우)로도 갱신한다. opencode 는 구독 남은 양을 알 수 없어서 「최근 7일 이 맥에서 쓴 양 — 토큰 · 비용」 만 보인다(`opencode stats` 를 못 읽으면 줄 없음). 앱은 로그인 셸의 PATH 로 CLI 를 찾는다. **앱이 띄우는 CLI 는 앱 전용 환경으로 따로 로그인해야 한다**(아래).
- **설정 창**: 메뉴 막대 아이콘 ▸ 「설정…」(⌘,). CLI 마다(클로드 · 제미나이 · ChatGPT · opencode) 설치 여부 · 로그인 상태(이메일 · 플랜만) · [로그인] · 남은 양(이름 · 사용 % 막대 · 초기화 시각) · [새로 고침]. 로그인 상태 · 남은 양은 설정 창을 열 때(넷 모두, 단 **앱 전용 HOME 방식의 제미나이는 자동으로 안 읽고** [새로 고침] · [로그인] 을 누를 때만 — `agy models` 가 키체인 창을 띄울 수 있어서)나 옆 창을 열 때(고른 CLI 만, 같은 규칙)만 읽고(앱을 켤 때는 아무 CLI 도 안 부름), 한 CLI 에 5분 안에는 다시 읽지 않으며(새로 고침은 읽음), 하나당 20초가 넘으면 「알 수 없음」 이다. 남은 양은 CLI 가 알려 주는 비공식 값이라 버전이 바뀌면 안 보일 수 있다.
- **제미나이(agy) — 두 방식(설정 창 제미나이 줄에서 고른다, 설정에 저장)**: agy 는 전용 설정 폴더 환경값이 없다. ① **앱 전용 폴더(시험판, 기본)** — 앱이 agy 에만 `HOME=~/Library/Application Support/SafariAttractionApp/agy-home`(0700)을 줘서 사용자 `~/.gemini` 를 안 읽게 한다. 단 이 방식은 맥 키체인을 못 찾게 돼서(`HOME` 이 바뀜) **로그인이 되는지 아직 모른다** — 앱 확인 때 판정한다. ② **내 설정 함께 쓰기** — 사용자 HOME 그대로(앱이 사용자 설정을 바꾸지 않는다). 대신 「내 제미나이 설정의 MCP 가 문서 폴더 안이면 허락 창이 뜰 수 있어요 — 터미널에서 `agy mcp disable safari-attraction` 으로 끌 수 있어요」 경고와 그 줄을 복사하는 단추가 뜬다. 로그인 상태는 전용 명령이 없어서 `agy models` 가 모델 목록을 내면 로그인됨, 「Please sign in」 이면 안 됨(그 목록이 모델 목록). 남은 양은 `agy -p "/usage" --output-format stream-json`(모델 호출 아님)의 남은 비율에서 사용 비율을 계산한다(초기화 시각이 1970-01-01 이면 「아직 시작 안 됨」). 묻기는 `agy -p "<질문>" --model <id> --output-format stream-json`(웹 검색을 켜면 질문 앞에 「웹에서 찾아서 답해 줘. 출처 주소도 적어 줘.」). **agy 의 도구 막기**: agy 는 `-p` 에서도 도구(`run_command` · `write_to_file` · `view_file` · `browser_*` · `call_mcp_tool` …)가 잔뜩 켜진 채 뜬다(`--mode plan --sandbox` 로도 목록이 그대로). 그래서 두 방식 모두 agy 호출(묻기 · `models` · `/usage`)에 `--settings '{"permissions":{"deny":["read_file(*)","write_file(*)","command(*)","read_url(*)","execute_url(*)","mcp(*)"]}}'` 를 붙인다(박정욱 agy 로 확인: 「ok」 는 되고 파일 읽기 · ls 는 도구 오류). **웹 검색을 켰을 때만 `read_url(*)` 을 뺀다**(검색 결과 페이지를 읽게). 대화는 agy 쪽 `conversations/` 에 남는다(끄는 옵션을 못 찾음).
- **opencode**: 앱 전용 환경 `XDG_CONFIG_HOME` · `XDG_DATA_HOME` · `XDG_STATE_HOME` · `XDG_CACHE_HOME`(= `~/Library/Application Support/SafariAttractionApp/opencode-xdg/{config,data,state,cache}`) + `OPENCODE_DISABLE_CLAUDE_CODE=1` · `OPENCODE_DISABLE_PROJECT_CONFIG=1` · `OPENCODE_DISABLE_AUTOUPDATE=1`, **모든 opencode 명령에 `--standalone`**(없으면 이 맥에서 상주하는 공용 서버로 가서 앱 전용 폴더를 안 쓴다). 도구 끄기: 앱이 앱 전용 `opencode-xdg/config/opencode/opencode.json` 을 쓴다(`permission` 전부 deny · `tools` 열둘 false — opencode 가 오류 없이 읽는 것은 확인, **실제로 막히는지는 로그인 뒤 맥 앞 확인**). 묻기는 `opencode run "<질문>" -m <공급자/모델> --format json --archived --standalone`, 웹 검색은 못 한다(켜면 「이 CLI 는 웹 검색을 못 해요 — 검색 없이 답해요」). 로그인 상태는 `opencode auth list --standalone` — 「No authenticated…」 면 「로그인 필요 — 로그인 없이 쓰는 무료 사용량은 금방 막혀요」(박정욱 맥에서 로그인 없이 무료 모델도 바로 `provider.free-limit` 으로 거절됐다)이고 칩도 다른 로그인 안 된 CLI 처럼 흐려진다. 묻기에서 그 거절이 오면 「opencode 무료 사용량이 다 찼어요 — 설정에서 opencode 로그인을 해 주세요」.
- **codex**: 묻기 전에 늘 `codex login status` 를 먼저 본다(로그인이 안 된 채 `codex exec` 를 돌리면 20초 넘게 재시도하므로) — 안 됐으면 프로세스를 띄우지 않고 「설정에서 ChatGPT 로그인을 해 주세요」. 질문은 `codex exec --json --skip-git-repo-check --ephemeral -s read-only -c cli_auth_credentials_store=file -c features.<기능>=false …(열아홉) [-m 모델]` 로 가고(읽기 전용 · 세션 파일 없음 · **도구 끄기**: `shell_tool unified_exec unified_exec_tty shell_snapshot computer_use browser_use browser_use_external browser_use_full_cdp_access in_app_browser apps plugins remote_plugin hooks multi_agent view_image image_generation skill_mcp_dependency_install workspace_dependencies worktrees` — 박정욱 codex 로 확인: 모두 끄면 답은 되고 「파일 목록을 명령으로」 는 「못 합니다」), 이어 묻기는 앞 대화(최근 6턴 · 4,000자)를 질문에 붙인다. codex 는 웹 검색을 못 한다 — 웹 검색을 켜면 답 위에 「이 CLI 는 웹 검색을 못 해요 — 검색 없이 답해요」.
- **로그인 단추**: 클로드는 터미널을 열어 `claude auth login --claudeai` 를 돌린다(코드 붙여넣기 단계가 있을 수 있어서). codex 는 앱이 `codex login --device-auth` 를 띄워 **주소와 일회용 코드**를 설정 창에 보여 주고 [주소 열기] 를 누르면 브라우저가 열린다(끝나면 상태를 새로 읽는다). 출력에서 주소 · 코드를 10초 안에 못 읽거나 읽기 전에 오류로 끝나면(예: 계정에서 기기 코드 로그인을 안 켬) 터미널로 같은 명령을 연다(codex 자신의 안내가 거기 보인다). 제미나이 · opencode 는 늘 터미널로: 제미나이는 `agy` 를 인자 없이(TUI 로그인 — 열기 전에 「로그인을 마친 뒤 /quit 을 입력해 끝내고 이 창을 닫으세요」 를 먼저 보인다), opencode 는 `opencode auth login --standalone`. 터미널 열기 = 지원 폴더에 `login-claude.command` · `login-codex.command` · `login-agy.command` · `login-opencode.command` 를 쓰고(실행 권한, 그 CLI 의 앱 전용 환경 포함 — 토큰 · 키는 담지 않는다) `NSWorkspace.open` 으로 연다(Apple 이벤트 없음). 터미널로 연 로그인은 설정 창이 다시 앞으로 오면 상태를 새로 읽는다. `.command` 는 이름 대신 **앱이 찾은 절대 경로**(못 찾으면 이름)로 CLI 를 부르고 앱의 로그인 PATH 를 `export` 한다.
- **일 맡기기 · 루틴은 클로드만.** 일 맡기기 칸에서는 CLI 칸이 클로드로 고정되고 「일 맡기기는 지금 클로드만 돼요」 가 보이며, 모델은 클로드 모델 안에서 고른 것이 일 맡기기 명령줄(`--model`)에 들어간다. 묻기로 돌아오면 고른 CLI 가 그대로다. 루틴은 늘 기본 모델(sonnet).
- 「아직 앱 확인 안 함」 — 위 CLI 고르기 · 모델 · 설정 창 · 로그인 · 사용량은 시험(출력 예시를 고정 글로)과 빌드까지만 했고, 실제 CLI · 화면은 맥 앞에서 확인해야 한다(특히 codex 기기 코드 출력 모양 · 앱서버 JSON-RPC 줄 · 클로드 `/usage` 글 · **제미나이 앱 전용 폴더 방식의 로그인** · agy 가 로그아웃일 때 `-p` 가 어떻게 끝나는지 · `opencode stats --json` 모양 · 로그인된 `opencode auth list` 모양 · opencode 오류 줄 모양).
- **웹 검색**: 클로드에 WebSearch · WebFetch 도구만 켠다(기본 꺼짐). **「이 페이지 함께」 와 같이 켜면** 페이지 글이 클로드를 움직여 WebFetch 로 다른 주소를 열게 할 수 있다 — 믿을 수 없는 페이지에서는 둘을 함께 켜지 않는다.
- **이 페이지 함께**: 지금 사파리 탭의 제목 · 주소 · 고른 글을 질문 앞에 붙인다(기본 꺼짐). **사생활 보호 창의 탭도 읽는다.**
- **멈춤 · 시간 상한**: 답이 오는 중에 「멈춤」, 180초가 넘으면 저절로 멈추고 한국어로 알린다.
- 대화 말풍선은 앱 안에만 있고(이번 실행 동안), 사파리-어트랙션 기억 폴더에 쓰지 않는다. 다만 이어 묻기를 위해 **claude CLI 자신이 앱 전용 폴더 `~/Library/Application Support/SafariAttractionApp/claude-config/projects` 에 세션 기록을 남긴다**(앱이 지우지 않는다 — 사용자 `~/.claude/projects` 가 아니다). 개발용 빌드(`DEV=1`)는 마지막 질문 · 답(앞 2,000자)을 `dev-last.json` 에 적는다. 작업 폴더는 `~/Library/Application Support/SafariAttractionApp/work`(빈 폴더).
- **긴 질문**: 앞 대화 · 페이지 글 · 질문을 합친 프롬프트가 UTF-8 20만 바이트(한글 약 6만 6천 자)를 넘으면 CLI 를 띄우지 않고 「질문이 너무 길어요」 라고 알린다.

## 앱 전용 CLI 설정 폴더 · 앱 띄우는 곳

- **앱이 띄우는 codex 는 `CODEX_HOME=~/Library/Application Support/SafariAttractionApp/codex-home`(0700) 로 뜬다**(인증은 그 폴더의 `auth.json` 파일 — `-c cli_auth_credentials_store=file`). 사용자의 `~/.codex` 는 읽지 않아서 **로그인도 설정 창에서 따로 한 번** 한다. 클로드 · codex 두 환경값은 한 사전으로 모든 실행기(묻기 · 상태 · 목록 · 남은 양 · 로그인)에 들어간다.
- **앱이 쓰는 설정 파일**: 앱 전용 폴더를 준비할 때(앱을 켤 때 · 로그인 파일을 쓸 때) `codex-home/config.toml` 을 쓴다 — 맨 위에 `cli_auth_credentials_store = "file"`, 맨 아래에 `[features]` 아래 위 열아홉 기능을 `= false`(표시줄로 감싼 앱 관리 덩어리만 맞추고 그 사이의 다른 줄은 그대로 둔다. 그래서 `login --device-auth` · `login status` · `debug models` · `app-server` · 터미널 로그인 어느 길로 가도 인증이 같은 파일에 저장되고, 기본이 키체인인 맥에서도 어긋나지 않는다). `exec` 의 `-c cli_auth_credentials_store=file` · `-c features.<기능>=false` 는 그대로 두어 이중이다(`--disable <기능>` 은 모르는 이름이면 `Unknown feature flag` 로 종료 1 이라 쓰지 않는다 — 다른 버전 codex 에서 묻기가 통째로 실패하므로). opencode 의 `opencode.json`(위)도 같은 때 쓴다. 두 파일은 0600.
- **앱 전용 폴더를 못 만들면**: 덮어쓰기 사전(경로 글자)은 늘 적용되고, CLI(묻기 · 상태 · 로그인 · 일 맡기기)는 하나도 띄우지 않고 「앱 전용 설정 폴더를 만들지 못했어요 — …」 를 알린다(안 그러면 사용자 `~/.codex` · `~/.claude` 로 되돌아간다).
- **키 값 환경변수는 자식에게 안 넘긴다**: `ANTHROPIC_API_KEY` · `OPENAI_API_KEY` · `CODEX_API_KEY` · `GEMINI_API_KEY` · `GOOGLE_API_KEY` (구독 대신 키로 과금되는 것을 막는다). 로그인 `.command` 도 `unset` 한 뒤 CLI 를 부른다.
- **앱이 띄우는 agy · opencode 도 앱 전용 환경으로 뜬다**: agy 는 `HOME=…/agy-home`(「앱 전용 폴더」 방식일 때만 — 시험판), opencode 는 `XDG_*` 넷 + 위 환경값 셋. 이 값들은 **그 CLI 를 띄울 때만** 자식 환경에 얹는다(실행 파일 이름으로 가린다) — 클로드 · codex 의 자식에는 `HOME` · `XDG_*` 가 들어가지 않는다. 사용자 환경에 같은 이름이 있어도 앱 값이 이긴다. 폴더는 없으면 0700 으로 만든다.
- **앱이 띄우는 모든 claude(묻기 · 일 맡기기 · 예약 루틴)는 환경값 `CLAUDE_CONFIG_DIR=~/Library/Application Support/SafariAttractionApp/claude-config` 로 뜬다**(없으면 앱이 0700 으로 만든다. 사용자 환경에 이미 `CLAUDE_CONFIG_DIR` 가 있어도 앱 값으로 덮는다). 이 폴더는 평소 쓰는 클로드 설정과 따로라서 **로그인도 따로 한 번** 해야 한다. 터미널에서:

  ```
  CLAUDE_CONFIG_DIR="$HOME/Library/Application Support/SafariAttractionApp/claude-config" claude auth login
  ```

  (설정 창의 [로그인] 이 같은 일을 터미널에서 해 준다 — `claude auth login --claudeai`.) 로그인이 안 돼 있으면 옆 창에 「앱 전용 클로드 로그인이 필요해요 — 터미널에서 한 번: …」 가 뜬다. 평소 클로드(`~/.claude`)의 설정 · 기록은 건드리지 않는다.
- **앱은 `~/Applications` 에서 띄운다.** `app/scripts/build.sh` 가 `app/.build/SafariAttractionApp.app` 를 만든 뒤 `~/Applications/SafariAttractionApp.app` 으로 복사하고(있으면 바꿔치기, `codesign -v` 로 확인) 「여기서 여세요: ~/Applications/SafariAttractionApp.app」 를 찍는다. 복사가 실패해도 빌드는 성공으로 두고 경고만 한다. 문서 폴더(`~/Documents/…/app/.build`) 안의 앱을 열지 않는다.

## 일 맡기기 (옆 창의 「일 맡기기」 칸)

입력 칸 위의 「묻기 / 일 맡기기」 칸으로 모드를 바꾼다(답하는 중에는 못 바꾼다). 일 맡기기에서는 웹 검색 · 이 페이지 함께 칸 대신 「사이트 허락」 단추가 있다. 클로드(sonnet)가 앱 안에 넣어 둔 사파리-어트랙션 서버(`Contents/Resources/safari-attraction/`)로 사파리를 움직인다. 입력 하나 = 클로드 프로세스 하나 + 동작 관문(유닉스 소켓) 하나이고, 다음 입력은 같은 세션을 이어 받는다(`--resume`).

- **작업 목록 카드(파란 테두리)**: 클로드는 계획 모드로 시작해 작업 목록을 먼저 낸다. [이대로 진행] 을 눌러야 움직인다. [고쳐 줘] 는 한 줄을 써서 보내면 클로드가 계획을 다시 낸다. [그만] 은 멈춤. 승인 전에는 읽기와 이동만 되고 페이지를 바꾸는 동작은 모두 거절된다.
- **동작 카드(주황)**: 승인 뒤 페이지를 바꾸는 동작(누르기 · 칸 채우기 · 체크 · 고르기 · 키 · 글자 · 페이지 코드 · 요청)이 사이트 허락 모드에 따라 카드로 온다 — 사이트 · 동작 · 대상 · 값(비밀번호 칸은 「(비밀)」). [허락] · [거절] · [이 사이트 늘 허락](그 사이트를 「다 허락」 으로 저장).
- **빨간 줄 카드**: 「되돌릴 수 없어 보이는 일」(결제 · 삭제 · 보내기 등 버튼 글로 서버가 판정) 또는 「알 수 없는 페이지 코드」(읽기 전용으로 읽히지 않는 페이지 코드 실행). 「다 허락」 사이트여도 되돌릴 수 없어 보이는 일은 늘 묻고, 빨간 카드에는 「이 사이트 늘 허락」 단추가 없다.
- **코드 카드(빨간)**: 클로드가 짠 `repl` 코드에 주의할 낱말(`constructor` · `process` · `require` · `child_process` · `Function` · `eval` · `globalThis` · `prototype` · `import(` · `__proto__`, 대소문자 구분 · 낱말 경계 — `page.evaluate` 는 걸리지 않는다)이 있으면 코드를 보여 주고 묻는다(계획 승인 전이어도).
- 답한 카드는 결과(허락함 · 거절함 · 시간이 지나 거절 · 멈춤 …)로 굳는다. 카드에 5분 안에 답이 없으면 거절하고, 일 하나가 15분을 넘으면 멈춘다(「멈춤」 단추는 늘 있다).
- **기다리는 동안**: 카드가 답을 기다리는 동안은 사파리가 뒤로 가도 옆 창이 숨지 않고(앞으로 가져오거나 포커스를 뺏거나 사파리를 건드리지 않는다), 메뉴 막대 아이콘이 종 모양(기다림)으로 바뀐다. 옆 창을 직접 닫아 둔 경우는 열지 않는다 — 5분 안에 열어 답하지 않으면 거절된다.
- **사이트 허락**: 사이트(호스트)마다 「읽기만 / 묻고 하기 / 다 허락」. 저장하지 않은 사이트는 「묻고 하기」. 옆 창의 「사이트 허락」 에서 바꾸고 지울 수 있다(`~/Library/Application Support/SafariAttractionApp/site-modes.json`).
- 진행 줄: 「작업 목록을 만드는 중이에요…」 · 「쿠팡에서 '장바구니 담기' 누름」 처럼 짧게.

### 한계

- 동작 관문은 **실수와 보통의 속임**(페이지 글에 속아 「결제하기」 를 누르는 것)을 막는 장치이고, 일부러 빠져나가는 코드까지 막는 벽은 아니다. `repl` 코드는 서버 안에서 돌지만 노출된 함수의 `constructor` 로 서버 프로세스에 닿을 수 있다. 앞의 주의 낱말 검사는 보통의 경우를 거를 뿐이고 `a['con'+'structor']` 같은 코드는 못 거른다. 더 단단하게(별도 프로세스 · OS 샌드박스) 할지는 정해지지 않았다.
- `repl` 코드는 런타임에서 `Page` 의 비공개 멤버나 심볼(`Object.getOwnPropertySymbols`)로 관문을 건너뛸 수 있다 — 일부러 가린 코드의 한계다.
- 새로고침 · 뒤로 · 앞으로 는 늘 허락이라, POST 결과 페이지에서 새로고침하면 폼이 다시 보내질 수 있다.
- 사이트 허락은 호스트가 정확히 같을 때만 맞는다(`coupang.com` 과 `www.coupang.com` 은 다른 사이트 — 사이트 허락 화면에도 한 줄 적어 두었다).
- 「다 허락」 사이트에서는 코드 실행(`evaluate`)도 묻지 않는다. 다만 결제 · 삭제 같은 되돌릴 수 없어 보이는 낱말이 든 식은 물어서 빨간 카드가 뜬다.
- 작업 목록(계획)이 비어 오면(클로드가 계획 글을 안 쓴 채 계획을 마치려 할 때) 앱이 답 글을 계획으로 쓰거나, 계획을 목록으로 먼저 써 달라고 두 번까지 자동으로 되돌린 뒤에도 비면 빈 카드를 띄우고 [이대로 진행] 을 막는다. 계획 글의 링크는 누를 수 없고 주소만 괄호로 보인다.
- 기억 폴더는 앱 전용(`~/Library/Application Support/SafariAttractionApp/memory`)이라 Claude Code 세션의 기억과 갈린다.
- 사람이 있는 일 맡기기에는 맥 알림이 없다(옆 창을 못 보면 카드는 5분 뒤 거절된다). 알림은 아래 「루틴」 의 「끝나면 알림」 에만 있다.

### 맥 허락 창 접점 (일 맡기기)

앱이 띄운 것이 앱 이름으로 허락을 묻는 자리와 피하는 법이다.

| 접점 | 피하는 법 | 맥 앞에서만 |
|---|---|---|
| claude 가 사용자 훅 · 플러그인 실행(문서 폴더) | `--setting-sources ""` | — |
| 서버 파일이 문서 폴더(`~/Documents/safari-attraction/dist`) | 빌드 때 `plugin/` 의 `run.sh` · `server.mjs` · `jxa/host.js` 를 앱 `Contents/Resources/safari-attraction/` 에 넣어 거기서 띄움(`build.sh` 가 없으면 빌드를 실패시킨다) | — |
| 기억 폴더(iCloud Drive) | `SAFARI_ATTRACTION_HOME=~/Library/Application Support/SafariAttractionApp/memory` | — |
| 화면 찍기(`screencapture` → 화면 기록) | `SAFARI_ATTRACTION_NO_PERMISSION_PROMPTS=1` 이면 서버가 먼저 화면 기록 허락을 확인하고 없으면 찍지 않고 한국어 안내(허락 창 없음) | 화면 기록을 켜려면 박정욱이 시스템 설정에서 |

| node 찾기 | `run.sh` 가 흔한 자리(nvm · 홈브루 등)를 직접 뒤져 18 이상을 고름 — 로그인 셸 불필요 | — |

## 저장한 일 · 루틴 (조각 4)

> **아직 앱을 띄워 확인하지 못했다.** 일정 계산 · 저장소 · 루틴 판정 · 돌기 전 확인 · 앱 안 시계 · 알림 규칙은 단위 시험(AppCore)으로 확인했고 빌드까지만 끝났다. 「저장」 · 「저장한 일」 · 「루틴」 화면, 시계가 실제로 도는 것, 깨어남 처리, 실제 클로드 · 사파리로 도는 것, 맥 알림 허락 창은 **박정욱이 맥 앞에 있을 때** 확인한다(아래 확인 목록). 사람 없음 명령줄 + 시험 관문으로 진짜 클로드가 목록 안 사이트를 읽는 것은 터미널에서 한 번 봤고(누르기 · 목록 밖 이동은 클로드가 아예 시도하지 않아 거절 장면은 단위 시험으로만 확인), 전체 터미널 확인은 따로 한다.

### 저장한 일

일 맡기기 입력 칸 오른쪽의 **「저장」** 으로 지금 입력한 글에 이름을 붙여 저장한다(보내지는 않는다). **「저장한 일」** 에서 불러오기(입력 칸에 글만 들어가고 바로 시작하지 않는다) · 고치기 · 지우기 · 「루틴으로」. 저장한 일을 지우면 그 일의 루틴도 함께 지워지고, 지우기 전에 몇 개가 지워지는지 한 줄로 묻는다. 저장 위치는 `~/Library/Application Support/SafariAttractionApp/routines.json`(깨진 파일은 `.bak` 으로 남기고 빈 것으로 시작).

### 루틴

**「루틴」** 에서 저장한 일 하나에 일정을 붙인다 — **매일 HH:MM · 고른 요일 HH:MM · N시간마다(1~24)**. 목록에서 다음 도는 시각 · 켜기/끄기 · **지금 한 번**(일정과 상관없이 바로, 아래 같은 규칙으로 · 꺼진 루틴도 가능) · 고치기 · 지우기를 하고, 아래에서 기록(최근 200개 중 30개, 클로드 답 앞 4,000자)을 본다.

- **앱 안 시계만 돈다.** 앱이 켜져 있고 **루틴이 하나라도 켜져 있을 때만** 30초마다 살핀다(켜진 루틴이 없으면 시계가 서 있다). 로그인 항목 · launchd 는 만들지 않는다 — 앱이 꺼져 있으면 안 돈다.
- **지나침 규칙**: 잠자기 · 앱 꺼짐으로 시각을 지나쳤으면 깨어난 뒤(또는 앱을 켠 뒤) 지난 지 60분 안이면 한 번 돌고, 넘었으면 「건너뜀(지나침)」 기록만 남긴다. 여러 번 지나도 몰려 돌지 않는다(가장 최근 한 칸만). 루틴을 **켜거나 일정을 바꾸는 순간**부터 센다(껐다 오래 뒤 켜도 지난 칸이 건너뜀으로 기록되지 않는다).
- **사람 일 맡기기가 먼저**: 일 맡기기 · 다른 루틴이 도는 중이면 루틴은 최대 30분 기다렸다 돈다(넘으면 「건너뜀」). 루틴이 도는 동안에는 일 맡기기 입력이 잠기고 「루틴 '이름' 도는 중」 한 줄이 보인다(「멈추기」 로 멈출 수 있다).

### 사람 없음 규칙 (읽기만 · 갈 수 있는 사이트 안에서만)

루틴은 사람이 없으니 카드에 답할 수 없다. 그래서 일 맡기기보다 훨씬 좁게 돈다.

- **읽기만 하도록 막는다**: 사이트 허락 모드와 상관없이 이동 · 새 탭 열기 · 읽기 전용 요청(GET · HEAD)만 되고, 누르기 · 칸 채우기 · 체크 · 고르기 · 키 · 글자 · 페이지 코드 · 쓰기 요청은 거절한다(「루틴은 읽기만 해요」). 기억 · 프로젝트는 찾기 · 읽기 · 목록만 되고 남기기 · 지우기 · 고치기는 앱과 서버가 둘 다 거절하며(거절 한 번으로 셈), 사용자가 열어 둔 사파리 탭을 읽거나 붙잡는 `listBrowserTabs` · `attachBrowserTab` · `attachActiveBrowserTab` 도 서버가 거절한다. 거절이 한 번이라도 있으면 기록이 「일부만 됨」.
- **갈 수 있는 사이트**: 루틴마다 목록이 있고, **목록 밖 사이트는 읽기 · 이동 · 새 탭 · 요청을 거절하도록 막아 둔다**(읽은 페이지에 심어 둔 속임 글이 값을 남의 주소로 내보내는 것을 막으려는 장치다. 서버가 모든 이동을 앱에 묻고 앱이 판정한다). 이 목록과 읽기만 규칙은 실수와 보통의 속임을 막는 장치이지 절대적인 벽이 아니다. 목록의 `coupang.com` 은 `www.coupang.com` · `m.coupang.com` 같은 아래 주소도 허락하고, `co.kr` 같은 공개 접미사는 목록에 못 넣는다. 루틴을 만들 때 **저장한 일 글에서 주소를 자동으로 뽑아 미리 채우고, 사람이 확인해 고치거나 더하고 뺀다.** 글에서 못 뽑으면 목록이 비는데, 그러면 화면이 경고하고 그 루틴은 클로드를 띄우지 않고 돌 때마다 「건너뜀(갈 수 있는 사이트가 없어요)」 로 끝난다(일정 실행 · 「지금 한 번」 모두).
- 클로드는 `--tools ""`(내장 도구 없음, 사파리 MCP 만) · 계획 모드 없음 · 카드 없음으로 돌고, 코드 실행에 주의 낱말이 들면 거절한다. 한 번에 10분이 넘으면 멈추고 「실패」.
- 결과: 끝남 · 일부만 됨 · 실패 · 건너뜀(이유).

### 맥 허락 창 — 루틴은 묻지 않는다

사람이 맥 앞에 없을 때 허락 창이 뜨면 그 자리에서 멈추므로, 루틴은 허락 창이 뜰 일을 **하지 않고 건너뛴다**.

- **사파리가 이미 켜져 있어야** 돈다. 꺼져 있으면 켜지 않고 「건너뜀(사파리가 켜져 있지 않아 건너뛰었어요)」. 서버도 사람 없음 모드에서는 사파리를 켜지 않고 새 창(AI 창)을 열지 않는다.
- **사파리 제어(자동화) 허락이 이미 있어야** 돈다. 확인은 `askUserIfNeeded: false` 로만 하고(허락 창을 띄우지 않는다), 허락이 없으면 「건너뜀(사파리 제어 허락이 아직 없어요 — 맥 앞에서 일 맡기기를 한 번 써 주세요)」. 처음에는 맥 앞에서 일 맡기기를 한 번 써서 허락해 둔다.
- **알림 허락은 사람이 「끝나면 알림」 을 켤 때만** 묻는다(앱을 켤 때 · 루틴이 끝날 때는 묻지 않는다 — 앱이 켜질 때 알림 센터에 허락을 요청하는 코드는 없다).

### 끝나면 알림

루틴 화면의 「끝나면 알림」 을 켜면 그때 맥이 알림 허락을 묻는다(맥 앞에서 켠다). 허락하면 **끝남 · 일부만 됨 · 실패**일 때 맥 알림을 보낸다. 건너뜀은 알리지 않고 기록만 남긴다. 허락이 없으면(거절했거나 나중에 껐다면) 알림 없이 기록만 남고, 켜려 해도 켜지지 않는다 — 시스템 설정 ▸ 알림에서 허락한 뒤 다시 켠다. 기록을 디스크에 못 썼을 때도 「실패(저장 실패)」 알림이 간다.

### 한계

- 앱이 꺼져 있거나 맥이 잠든 동안에는 안 돈다(깨어나면 지나침 규칙대로). 앱 밖 예약(launchd)은 없다.
- 이 앱은 사파리가 **이미 떠 있고** 자동화 허락이 **이미 있을 때만** 돈다. 사파리를 켜지 않으니 사파리를 닫아 둔 날은 모두 건너뜀이다.
- 사이트 목록의 도메인 뽑기는 휴리스틱이라 글에 따라 틀릴 수 있다(한글 도메인 · `localhost` 는 못 뽑고, `문장.Next` 같은 붙여 쓴 글이 도메인으로 뽑힐 수 있다) — 그래서 저장 전에 사람이 확인한다. `gov.uk` 같은 목록 밖 공개 접미사는 막지 않는다(21개만 막음).
- 읽기 전용 페이지 코드(evaluate)는 사람 없음에서도 묻지 않는다(관문이 이동 · 요청만 묻는다). 이동은 서버가 푼 주소로만 하지만, 이동 뒤 서버가 받은 리다이렉트의 도착지는 `fetch` 만 다시 확인한다(`goto` 리다이렉트 · 뒤로 가기 이력은 한계 — 서버 README).
- 루틴은 사용자의 사파리 로그인 상태로 돈다. 사이트 목록을 좁게 두는 것이 안전 장치의 큰 몫이다. 사이트 목록과 읽기만 규칙은 실수와 보통의 속임을 막는다. 속임 글에 넘어간 클로드가 일부러 빠져나가는 코드를 쓰면 막지 못한다(조각 3 관문과 같은 한계) — 그래서 로그인해 둔 중요한 사이트(메일 · 은행 등)를 루틴 목록에 넣는 것은 권하지 않는다.
- 클로드 답(앞 4,000자)이 앱 지원 폴더의 기록 파일(`routines/history.jsonl`)에 남는다 — 읽은 페이지 내용이 들어갈 수 있다. 맥 알림에는 루틴 이름과 상태만 실리고 클로드 답 · 읽은 내용은 싣지 않는다.
- 루틴을 켜거나 「지금 한 번」 을 누르면 앱이 로그인 셸 PATH 를 메인 밖에서 미리 읽어 캐시한다(사람 없는 시각의 첫 실행이 `zsh -lic` 를 처음 부르지 않게). 이미 읽어 두었으면 다시 읽지 않는다.
- 한 번에 하나만 돈다. 돌고 있는 루틴은 앱을 끝낼 때 멈춘다.

### 맥 앞에서 확인할 것 (아직 안 함)

앱을 띄워 보며 아래를 확인한다. 하나라도 어긋나면 알려 준다.

1. 일 맡기기에서 글을 쓰고 「저장」 → 이름 입력 → 「저장한 일」 에 보임, 「불러오기」 로 입력 칸에 글이 들어가고 바로 시작하지 않음, 고치기 · 지우기(루틴이 달린 일은 「루틴 N개도 지워져요」 확인 글).
2. 「루틴으로」 → 사이트 칸에 글의 주소가 미리 채워짐 · 고치기 · 비우면 경고 · 일정 종류 셋 저장 · 다음 시각이 맞음.
3. 켜진 루틴을 1~2분 뒤로 잡아 시계가 그 시각에 도는지(앱 켠 채), 도는 동안 일 맡기기 입력이 잠기고 「루틴 '…' 도는 중」 이 보이는지, 끝나면 기록이 생기는지.
4. 사파리를 끈 채 시각이 되면 「건너뜀(사파리가 켜져 있지 않아…)」 이고 **사파리가 켜지지 않는지**. 사파리 제어 허락을 일부러 빼 두었을 때(시스템 설정 ▸ 개인정보 보호 및 보안 ▸ 자동화) 허락 창 없이 「건너뜀(허락이 아직 없어요…)」 인지.
5. 맥을 재웠다 깨울 때: 60분 안이면 한 번 돌고, 넘으면 「건너뜀(지나침)」 한 줄만(깨어난 뒤 몇 초 안에).
6. 「지금 한 번」 — 꺼진 루틴에서도 돌고, 사람 일 맡기기가 도는 중엔 눌리지 않는지.
7. 「끝나면 알림」 을 켤 때 처음으로 맥 알림 허락 창이 뜨는지(앱을 켤 때는 안 뜸). 허락하면 루틴이 끝났을 때 알림이 오고, 건너뜀에는 안 오는지.
8. 실제 클로드로 도는 루틴이 목록 안 사이트를 읽고 정리해 답하는지, 목록 밖으로는 못 가는지(기록이 「일부만 됨」).

## 맥 허락 창 (맥 앞에서)

앱은 ad-hoc 서명이라 맥이 허락을 이 앱 이름으로 묻는다. ad-hoc 서명은 빌드할 때마다 앱 지문(cdhash)이 바뀌어, **다시 빌드하면 맥이 새 앱으로 보고 허락을 다시 물을 수 있다**(같은 빌드에서는 다시 안 묻는다 — 실제로는 아직 확인 못 함). 빌드가 바뀌어도 허락이 남게 하려면 무료 Apple ID 의 개발 인증서로 서명해야 한다(조각 2 에서 Xcode 를 쓸 때). **맥 앞에 있을 때 처음 써 보세요** — 아무도 안 누른 허락 창이 떠 있으면 그 질문은 창에서 멈춘다.

- **자동화(사파리 제어)**: 「이 페이지 함께」 · 옆 창 따라가기에 필요하다. 거절해도 대화는 된다(옆 창이 사파리를 못 따라가고, 페이지는 안 붙는다).
- **문서 폴더 접근**: 「묻기」 를 처음 보냈을 때 맥이 「SafariAttractionApp … 문서 폴더」 허락 창을 띄운 일이 있었다. 원인은 **사용자의 클로드 설정이 문서 폴더 경로를 가리키는 것** — claude 가 시작하면서 `~/.claude.json` 의 프로젝트 경로 · `~/.claude/plugins/known_marketplaces.json` 의 문서 폴더 안 로컬 장터를 읽으러 가고, 앱 이름으로 허락이 물렸다(`--safe-mode` 로도 안 막혔다). 터미널에서 문서 폴더 접근을 막고(sandbox-exec) 같은 조건으로 돌려 확인했다: 로그인 셸(`zsh -lic`)은 문서 폴더에 안 닿고, `claude -p … --safe-mode` 는 닿고, **`CLAUDE_CONFIG_DIR` 를 빈 폴더로 두면 안 닿는다.** 그래서 앱은 claude 를 앱 전용 설정 폴더로 띄운다(위 「앱 전용 클로드 설정」 — 한 번 로그인해야 한다). 이 맥에서 앱 화면으로 다시 확인한 것은 아직 아니다.
  - **앱 자신도 로그인 셸을 돌린다**: 첫 질문을 보낼 때 앱이 `claude` 를 찾으려고 로그인 셸(`/bin/zsh -lic`)로 PATH 를 한 번 읽는데, 이때 사용자의 rc 파일(`.zshrc` 등)이 실행된다. rc 가 문서 폴더를 읽으면 그 첫 질문에서 허락 창이 뜰 수 있다(앱이 켜질 때는 읽지 않는다). 터미널 확인에서는 로그인 셸이 문서 폴더에 닿지 않았다.
  - 클로드는 `--safe-mode` 로 띄워 사용자 훅 · 플러그인 · CLAUDE.md 를 불러오지 않게 했다. 터미널에서는 훅 0 · MCP 0 으로 구독 답 · 웹 검색이 되는 것을 확인했다(앱에서 띄운 확인은 아직). `--safe-mode` 는 이 맥의 claude 2.1.330 에서 확인했고, 옛 버전에는 없을 수 있다.
  - 제미나이(`agy`) 「내 설정 함께 쓰기」 방식은 조심: 세션만 MCP 서버를 끄는 옵션이 없어 `~/.gemini/config/mcp_config.json` 의 MCP 서버를 그대로 띄우고, 그중 문서 폴더 안에 있는 서버가 있으면 처음 한 번 묻는다(`agy mcp disable safari-attraction` 으로 끌 수 있다 — 설정 창에 경고 · 복사 단추). 「앱 전용 폴더」 방식은 사용자 MCP 를 안 읽지만 키체인 문제가 있다(위).

## 알려진 한계

- 이 맥에서만 돈다(서명 인증서 없음 · 공증 없음). 다른 맥으로 옮기려면 유료 개발자 계정이 필요하다.
- 앱이 강제 종료 · 충돌로 죽으면 돌던 claude 가 남을 수 있다(정상 종료는 정리한다).
- 조각 2(페이지 위 패널) 전까지는 사파리 안에서 부를 수 없다 — 옆 창 · 단축키(⌘E)만.
