# 사파리-어트랙션

Claude 가 사용자의 실제 로그인된 사파리를 몰 수 있게 하는 로컬 TypeScript MCP 서버. 계속 떠 있는 `osascript -l JavaScript` 프로세스 하나로 사파리를 움직이고, Aside 브라우저의 `repl` 처럼 자바스크립트 한 덩어리로 열기 · 읽기 · 입력 · 클릭을 한다. 새 탭은 뒤쪽 탭으로 열려 사용자 화면을 가로채지 않는다. 서버가 끝나면 Claude 가 연 탭은 모두 닫힌다(사용자 탭은 건드리지 않는다).

macOS 와 사파리가 필요하다. Node 는 플러그인 · 홈브루(자동으로 깔림) · 소스 빌드 때만 쓴다(플러그인 Node 18 이상, 소스에서 빌드 · 시험은 Node 20 이상). `.mcpb` 는 Claude 앱이 가진 Node 를 쓴다.

## 설치

내 쓰임에 맞는 길 하나만 고른다. 세 길 모두 같은 서버(`repl` · `status` · `memory` · `project` 도구)를 깐다.

| 이런 분께 | 길 |
| --- | --- |
| Claude Code 를 쓴다 | 플러그인(한 줄) |
| 터미널은 쓸 줄 안다(Claude Code · Claude 앱 둘 다 연결하고 싶다) | 홈브루(세 줄) |
| 터미널이 낯설다(Claude 앱만 쓴다) | `.mcpb` 파일(더블클릭) |

저장소는 공개라 세 길 모두 GitHub 로그인 없이 설치된다. `.mcpb` 는 [릴리스](https://github.com/gulzzaang/safari-attraction/releases/latest)에서 받는다.

### 길 1. Claude Code 플러그인

Claude Code 안에서 한 줄:

```
/plugin install safari-attraction --marketplace gulzzaang/safari-attraction
```

또는 두 줄로:

```
/plugin marketplace add gulzzaang/safari-attraction
/plugin install safari-attraction@safari-attraction
```

GitHub 로그인이 안 돼 있으면 저장소를 내려받은 폴더로 설치한다(GitHub 로그인 불필요):

```
/plugin marketplace add ~/Documents/safari-attraction
/plugin install safari-attraction@safari-attraction
```

플러그인은 `plugin/server.mjs`(부품을 한 파일로 묶은 서버)를 그 맥의 `node` 로 띄운다. Node 는 `plugin/run.sh` 가 알아서 찾으니(PATH · 홈브루 · nvm · volta · asdf · fnm) Dock 에서 켠 Claude Code 에서도 되고, Node 18 이상이 있어야 한다. 설치 뒤 새 세션부터 도구가 보인다.

### 길 2. 홈브루

```sh
brew tap gulzzaang/safari-attraction https://github.com/gulzzaang/safari-attraction
brew install safari-attraction
safari-attraction setup
```

`setup` 이 Claude Code 와 Claude 앱(데스크톱) 설정에 `safari-attraction` 을 등록한다. 설정 파일을 고치기 전에 같은 폴더에 `…bak-<날짜시각>` 사본을 남기고, 우리 항목 말고는 건드리지 않는다. 먼저 보고 싶으면 `safari-attraction setup --dry-run`(아무것도 쓰지 않고 할 일만 출력), 한쪽만 하려면 `--no-claude-code` 또는 `--no-desktop`. 플러그인이 이미 깔려 있으면 Claude Code 쪽은 건너뛴다. 등록 경로는 `$(brew --prefix)/opt/safari-attraction/bin/safari-attraction` 이라 `brew upgrade` 뒤에도 그대로 살아 있다. 등록한 뒤 Claude 를 새로 시작한다.

### 길 3. Claude 앱 확장(`.mcpb`)

1. 이 저장소의 GitHub 릴리스 페이지(최신 버전)에서 `safari-attraction-<버전>.mcpb` 를 받는다(받아서 전달받아도 된다).
2. 파일을 더블클릭하면 Claude 앱이 열리며 설치 창이 뜬다. **「설치」** 를 누른다.
3. Claude 앱을 새로 시작하면 도구가 보인다.

### 공통 준비(처음 한 번)

길과 상관없이 필요하다.

1. 사파리 ▸ 설정 ▸ 고급 ▸ **웹 개발자용 기능 보기** 켜기.
2. 메뉴 막대 **개발** ▸ **Apple 이벤트의 JavaScript 허용** 켜기.
3. 처음 쓸 때 macOS 가 「자동화」 허락(터미널이나 Claude 가 사파리를 제어해도 되는지)을 묻는다. 허락해야 한다. 막혔다면 시스템 설정 ▸ 개인정보 보호 및 보안 ▸ 자동화에서 켠다.
4. 화면 찍기(`page.screenshot()`)를 쓸 때만: 아래 「화면 기록 권한」.

### 점검

- Claude 에게 `status` 도구를 불러 보라고 하면 무엇이 꺼져 있는지 한국어로 알려 준다. 맨 아래에 기억 폴더 줄(위치 · 쓸 수 있는지 · 충돌본 · 마지막 정리)도 붙는다.
- 터미널에서는 `safari-attraction doctor`(홈브루로 깐 경우). 사파리 준비가 모두 됐으면 0, 아니면 1 로 끝난다(기억 폴더 줄은 종료 코드에 영향이 없다 — 기억 폴더를 못 써도 사파리 조작은 된다). 버전은 `safari-attraction --version`.

### 같은 도구가 두 번 보일 때

두 길 이상으로 깔면 `repl` · `status` · `memory` · `project` 가 두 벌 보인다. 하나만 남기고 지운다.

| 지울 것 | 방법 |
| --- | --- |
| `setup` 이나 직접 등록한 Claude Code 연결 | `claude mcp remove --scope user safari-attraction` |
| 플러그인 | Claude Code 안에서 `/plugin uninstall safari-attraction` |
| `.mcpb` 확장 | Claude 앱 ▸ 설정 ▸ 확장에서 사파리-어트랙션을 지운다 |

`safari-attraction setup` 은 Claude Code 에 플러그인이 이미 있으면 등록하지 않는 식으로 겹침을 피하지만, 플러그인을 나중에 깔면 겹칠 수 있다. Claude 앱 설정에 `setup` 으로 등록한 항목과 `.mcpb` 가 겹칠 때는 `claude_desktop_config.json` 의 `safari-attraction` 항목을 지우거나 확장을 지운다.

### 소스에서 직접 등록(개발용)

```sh
npm install
npm run build        # dist/ 와 plugin/server.mjs 를 함께 만든다
claude mcp add --scope user safari-attraction -- <node 절대경로> <저장소 경로>/dist/src/index.js
```

`<node 절대경로>` 는 `which node` 로 확인한다(Node 20 이상). 등록한 뒤 새 세션부터 도구가 보인다.

## 도구 네 개

- `repl` — 사파리를 자바스크립트로 조작한다. `openTab(url)`, `attachActiveBrowserTab()`, `snapshot()`, `page.locator(...).click()/.fill()`, `page.evaluate(...)`, `fetch(url)` 등. 최상위 `await` 가 되고 `const` · 함수는 다음 호출에도 남는다. 값은 `console.log` 로 찍어야 보인다. 자세한 사용법은 도구 설명에 들어 있다. 계획 2에서 아래 기능이 더해졌다.
  - **AI 창** — `openAiWindow(url, {width, height})` 가 Claude 전용 사파리 창을 사용자 창 맨 뒤에 열고(앞 앱을 안 바꾼다) 그 안의 탭을 돌려준다. `page.setViewportSize({width, height})` 로 휴대폰 폭(390×844 등)을 맞춘다. 실제 크기를 돌려주고, 사파리 창은 약 336px 보다 좁게 못 줄이며 화면 높이가 작으면 높이는 그만큼만 나온다(이 개발 맥은 안쪽 높이가 약 795px 에서 멈춘다). 백그라운드 탭의 `innerWidth` 는 그 탭이 앞에 보일 때까지 늦게 바뀔 수 있다.
  - **찍기** — `page.screenshot()` 이 AI 창 전체(주소창 포함)를 PNG(긴 변 1568px 이하)로 찍고, `display(buf)` 로 결과에 붙인다(한 호출 4장까지). `useAiWindow(id)` 로 지정한 창에서는 찍을 때 그 창의 보이는 탭이 찍는 페이지로 바뀌고 되돌리지 않는다. AI 창은 사용자 창 뒤에 있어 사파리가 그 페이지를 숨김으로 보고하므로, 찍을 때마다 그리기를 최대 1초쯤 기다린다(화면 기록 권한이 있는 맥에서 다시 확인할 것).
  - **창 고르기** — `listWindows()` 가 열린 창(`id`, 현재 탭 제목, 탭 수, 크기, AI 창 · 작업 창 여부)을 보여 주고, `useWindow(id)` 로 `openTab` 이 열릴 창(그 창의 프로필을 따른다)을, `useAiWindow(id)` 로 이미 열어 둔 창을 AI 창으로 고른다. 사용자 창은 닫지 않는다.
  - **깊은 읽기** — `snapshot()` 이 열린 shadow DOM 과 같은 사이트 iframe 안쪽까지 읽는다.
- `status` — 빠진 준비를 한국어로 점검한다: 사파리 실행, 자동화 허락, 「Apple 이벤트의 JavaScript 허용」, 화면 기록(찍기용) 네 가지를 ✓ / ✗ / ? 로 보여 주고 고칠 곳을 알려 준다. 빈 탭을 잠깐 열었다 닫는다. 맨 아래에 기억 폴더 줄이 함께 나온다.
- `memory` · `project` — 기억과 프로젝트. 아래 「기억 · 프로젝트」 절.
- 자주 가는 사이트의 안내서는 도구가 아니라 `repl` 의 `guide()` 로 본다. 아래 「사이트 안내서」 절.

## 기억 · 프로젝트

Claude 가 사파리로 한 일을 기억해 두고, 오래 걸리는 일(예: 이사 준비)을 프로젝트로 묶어 다음 대화에서 이어 갑니다. 따로 설정할 것은 없습니다. 평소처럼 말하면 됩니다.

### 어디에 저장되나요

전부 내 맥의 폴더 안 **마크다운(.md) 글 파일**입니다. 메모장이나 옵시디언으로 바로 열 수 있고, 다른 서버에 올리지 않습니다(iCloud 폴더면 iCloud 가 내 다른 맥과 맞춥니다).

| 상황 | 폴더 |
| --- | --- |
| 보통(iCloud Drive 를 쓰는 맥) | iCloud Drive 안 `사파리-어트랙션` 폴더(`~/Library/Mobile Documents/com~apple~CloudDocs/사파리-어트랙션/`) |
| iCloud Drive 가 아예 없는 맥 | `~/Library/Application Support/safari-attraction/`(이 맥에만 저장) |
| 직접 정하고 싶을 때 | 환경 변수 `SAFARI_ATTRACTION_HOME` 에 폴더 경로 |

폴더에 쓸 수 없으면(권한 문제 등) 다른 곳으로 몰래 옮기지 않고 「기억 폴더에 쓸 수 없어요」 라고 알려 줍니다. 그때도 사파리 조작은 그대로 됩니다. `status` 로 지금 폴더와 상태를 볼 수 있습니다.

```
사파리-어트랙션/
├─ 기억/
│  ├─ 나.md                    나에 대해 기억해 둔 것(취향 · 습관)
│  ├─ 사이트/coupang.com.md …  사이트마다 메모(예: 「로켓배송만 본다」)
│  ├─ 일지/2026-11-23-<맥 이름>.md   하루 기록(맥마다 따로)
│  └─ 오래-기억.md             정리하고 남긴, 오래 두고 볼 것
└─ 프로젝트/
   └─ 이사 준비/               프로젝트.md · 문서/ · 기록-<맥 이름>.md
```

### 무엇이 남고 무엇이 안 남나요

- **남는 것** — Claude 가 사파리로 사이트를 열거나 옮겨 갔을 때(또는 실패했을 때) 하루 기록에 한 줄: 시각 · Claude 가 붙인 작업 이름(그 호출의 제목) · 사이트 주소 · 성공 여부 · 열려 있던 프로젝트. 사이트 메모가 있으면 그 사이트를 처음 열 때 결과 끝에 한 번 붙습니다(600자 이내).
- **안 남는 것** — 주소의 `?` 뒤(검색어 등)와 `#` 뒤는 버립니다. 길고 알 수 없는 문자열(주문 번호 · 토큰 같은 것)은 가립니다. 내가 이미 열어 둔 탭을 Claude 가 읽을 때는 사이트 이름(도메인)만 남깁니다. 페이지 내용은 저장하지 않습니다.
- **민감한 값은 저장을 거절합니다** — 카드 번호, 「비밀번호:」 · 「비밀번호는 …」 · `password:` · `pw …` 같은 비밀번호, 인증 번호(OTP), `sk-` · `ghp_` 같은 키 · 토큰이 든 글은 「기억해」 라고 해도 저장하지 않고 이유를 알려 줍니다.
- **기록을 멈추려면** — 「이번 대화는 기록하지 마」 라고 하면(`memory` 의 `pause`) 그 대화 동안 하루 기록을 멈춥니다. 「다시 기록해」 로 되돌립니다. 30분 동안 아무 일이 없으면 새 대화로 보고 처음 상태로 돌아갑니다.

### 이렇게 말해 보세요

- 「쿠팡은 로켓배송만 봐 줘, 기억해」 — 쿠팡 사이트 메모에 저장합니다.
- 「이사 준비 프로젝트 만들어 줘」 — 프로젝트를 만듭니다. 조건 · 사이트 · 문서(비교표 등)를 계속 모아 둡니다.
- 「이사 준비 이어서 해 줘」 — 프로젝트를 열어 지난번 상태에서 이어 갑니다. 「모아 둔 사이트 다 열어 줘」 라고 하면 뒤쪽 탭으로 한꺼번에 엽니다.
- 「지난주에 본 노트북 찾아 줘」 — 하루 기록 · 메모 · 프로젝트에서 찾아 줍니다.
- 「기억 정리해 줘」 — 지난 하루 기록들을 요약해 오래 둘 것만 남기고, 원본은 `보관` 폴더로 옮깁니다(찾기에는 계속 나옵니다). 하루가 지난 기록이 쌓이면 Claude 가 한 번 알려 줍니다.
- 「이건 잊어 줘」 — `나.md` 와 사이트 메모에서 그 글이 든 줄을 지웁니다. 정리해서 남긴 `오래-기억.md` 와 프로젝트 메모는 지우지 않으니, 파일을 직접 고치거나 `project` 의 `update` 로 바꾸세요.
- 긴 문서 · 기억 파일은 한 번에 8KB 까지만 읽어 줍니다. 더 길면 끝에 적힌 `offset` 으로 이어서 읽습니다.

### 맥이 두 대일 때

iCloud 로 폴더가 같이 보이면 두 맥이 같은 기억을 씁니다. 하루 기록과 프로젝트 기록은 **맥마다 따로 된 파일**(이름 끝에 맥 이름)이라 서로 덮어쓰지 않습니다. 사이트 메모 · `나.md` · `프로젝트.md` 처럼 두 맥이 함께 쓰는 파일은 내가 시킬 때만 바뀝니다. 그래도 두 맥이 거의 동시에 같은 파일을 고치면 iCloud 가 `이름 2.md` 같은 **충돌본**을 만듭니다. 자동으로 합치지 않고, `status` 가 파일 이름(3개까지)을 알려 줍니다. 두 파일을 열어 직접 합치고 충돌본을 지우세요.

두 맥의 이름이 같으면 맥별 파일이 한 파일에 섞이니, 한쪽 이름을 바꿔 주세요(시스템 설정 → 일반 → 정보). 이 맥의 이름은 `status` 의 「이 맥 이름」 줄에 나옵니다.

### 직접 열어서 고치기

Finder 에서 `사파리-어트랙션` 폴더를 열어 파일을 메모장이나 옵시디언으로 열고 마음대로 고치거나 지워도 됩니다. Claude 가 다음에 읽을 때 바뀐 대로 쓰입니다.

프로젝트를 **보관**하면(「이사 준비 보관해 줘」) `프로젝트/보관/` 으로 옮겨지고, 보관한 프로젝트는 열거나 고칠 수 없습니다(찾기에는 나옵니다). 보관은 한 방향입니다. 되살리려면 폴더를 직접 `프로젝트/` 안으로 옮기세요.

## 사이트 안내서

자주 가는 사이트는 어디에 무엇이 있고 어떻게 찾으면 되는지, 미리 적어 둔 **안내서**가 서버 안에 들어 있습니다. 따로 설정할 것은 없습니다. Claude 가 처음부터 화면을 더듬지 않고 바로 일하라고 있는 것입니다.

### 있는 안내서 10편

쿠팡 · 네이버 첫 화면과 검색 · 네이버 쇼핑 · 네이버 지도 · 지메일 · 구글 캘린더 · 구글 드라이브 · 유튜브 · 노션 · 깃허브. 주소 끝말이 맞으면 붙습니다(예: `cafe.naver.com` 은 네이버 첫 화면 · 검색 안내서). 안내서가 없는 사이트에는 아무것도 붙지 않습니다.

### 자동으로 붙는 것

- Claude 가 그런 사이트를 처음 열면 결과 끝에 **짧은 요약**(400자 이내)이 한 번 붙습니다. 같은 대화에서 같은 안내서는 다시 붙지 않습니다. 30분 동안 아무 일이 없으면 새 대화로 봅니다.
- 한 번에 요약은 두 편까지입니다. 사이트를 여러 곳 한꺼번에 열면 나머지는 「안내서 있음」 이름만 알려 줍니다. 그 사이트를 다룰 때 붙습니다.
- 내가 남긴 사이트 메모가 같이 있으면 **내 메모가 먼저**, 안내서 요약이 그 뒤에 붙습니다.
- 기억 폴더가 없거나 `memory pause` 중이어도 안내서 요약은 붙습니다. 안내서는 파일을 읽지 않고 서버 안에 들어 있기 때문입니다.

### 전체를 보고 싶을 때

`repl` 에서 `console.log(guide())` 는 지금 열린 페이지 사이트의 안내서 전체를, `guide("coupang.com")` 은 그 주소의 안내서 전체를 보여 줍니다. `console.log(guide.list())` 는 있는 안내서 목록입니다. 없는 사이트를 물어도 오류 없이 「아직 없어요」 와 있는 곳 목록으로 답합니다.

### 결제 · 보내기는 늘 사용자 확인

안내서가 있어도 결제 · 주문 · 메일 보내기 · 지우기 · 공유 · 초대처럼 되돌리기 어려운 일은 Claude 가 **멈추고 사용자에게 먼저 묻습니다**. 안내서에도 그 단추 이름을 「사용자 확인이 꼭 필요한 일」 로 적어 두었습니다. 로그인이나 인증 코드는 안내서가 다루지 않습니다.

### 안내서가 틀렸을 때

사이트 화면은 바뀝니다. 안내서마다 맨 끝에 「확인한 날」 이 적혀 있으니 오래됐으면 의심하세요. 고치려면 `src/guides/sites/` 안 그 사이트 파일(`coupang.ts` 등)의 글을 고치고 `npm run build` 로 묶음을 다시 만듭니다. 요약은 400자 · 전체는 6,000바이트 안이어야 하고 `npm test` 가 이를 확인합니다.

## 화면 기록 권한(찍기용)

`page.screenshot()` 은 macOS 의 화면 기록 권한이 있어야 한다. 시스템 설정 ▸ 개인정보 보호 및 보안 ▸ **화면 및 시스템 오디오 녹음** 에서 Claude 를 돌리는 앱(터미널 · Claude 앱 등)을 켜고, 그 앱을 다시 시작한다. 없으면 찍기가 `SCREEN_CAPTURE_DENIED` 안내 오류를 내고 다른 기능은 그대로 된다. 화면이 잠겨 있어도 찍지 못한다.

## 알려진 한계

- `snapshot()` 은 닫힌 shadow root 와 다른 사이트(또는 sandbox 된) iframe 안쪽을 읽지 못한다. 그런 곳은 한 줄로만 보이고 안쪽은 읽지 않는다. 그 안에서 Enter 로 제출해 이동하는 것은 이동으로 감지되지 않을 수 있다.
- `page.evaluate` 는 함수 하나나 식 하나만 받는다(여러 문장은 함수로 감싼다). 결과는 JSON 으로 오가서 DOM · 함수는 돌려받지 못하고, 바깥 변수는 못 쓰니 인자로 넘긴다.
- `fetch` 는 현재 `page` 안에서 돌아 그 페이지의 쿠키로 나가고 CORS · CSP 를 따른다. 돌려주는 값은 `{status, ok, statusText, url, headers(보통 객체), text(), json()}` 모양이다.
- `await` 뒤에서 이벤트 루프를 막는 코드(예: `await x; while (true) {}`)는 서버를 멈출 수 있다. 쓰지 않는다.
- 입력 · 클릭은 진짜 마우스 · 키보드가 아니라 페이지 안 이벤트로 보내진다.
- 사파리 스크립트로는 개인정보 보호 창과 일반 창을 구별할 수 없어 맨 앞 창을 그대로 쓴다. 개인정보 보호 창이 맨 앞이면 거기에 탭이 열릴 수 있다.
- 서버가 정리 단계를 거치기 전에 강제로 죽으면(SIGKILL 등) Claude 가 연 탭 · 창이 그대로 남을 수 있다. 그럴 땐 직접 닫는다.
- 우리 탭 닫기와 사용자 탭: 우리가 연 탭은 끝낼 때 닫는다. 그때 우리 탭인지는 페이지 안에 적어 둔 표시(우리 탭에만 적는 값)가 정확히 같을 때만 알아본다. 사용자 탭은 이 표시가 없으므로 건드리지 않는다. 다만 아래 드문 경우는 예외라서 사용자 탭에 우리 표시가 적히거나 사용자 탭이 닫힐 수 있다.
  - 우리가 한 동작(클릭 · 이동)으로 우리 탭에 새 문서가 떠 표시가 지워지면 표시를 다시 적는다. 우리가 그 탭의 표시를 마지막으로 확인한 지 60초 안이고 창의 탭 수 · 바로 앞뒤 탭 주소가 그때와 똑같고 그 자리의 탭이 http(s) 일 때만이다. 그 60초 안에 사용자가 우리 탭을 닫고 같은 자리에 새 탭을 열어 탭 수 · 이웃이 똑같아지면 그 새 탭에 표시가 적히고 끝낼 때 닫힐 수 있다. 60초가 지났거나 확인한 모습이 없을 때는 그 자리 탭의 주소가 우리가 기록한 주소(또는 가는 중이던 주소)와 정확히 같을 때만 표시를 적는다. 사용자가 우리 탭을 닫고 같은 자리에 똑같은 주소의 탭을 열었다면 그 탭이 닫힐 수 있다.
  - 우리 탭이 서버가 지켜보지 않는 사이 같은 사이트의 새 문서로 바뀌어 표시가 지워졌다면(예: 로그인 뒤 이동) 마지막으로 한 일로부터 10분 안이고 창의 탭 수 · 바로 앞뒤 탭 주소가 마지막으로 훑어 둔 모습과 똑같을 때 다시 우리 탭으로 본다. 그 사이 사용자가 우리 탭을 닫고 같은 사이트의 새 탭을 정확히 그 자리에 열어 탭 수 · 이웃이 똑같아지면 그 새 탭을 우리 탭으로 보고 닫을 수 있다.
  - 탭을 여는 몇 초 동안 우리 탭이 다른 주소로 넘어가는 중에 사용자가 같은 창 맨 끝에 탭을 열면(열려던 주소와 정확히 같거나 우리 탭을 막 닫은 순간이면) 그 탭에 우리 표시가 적히거나 우리 탭으로 등록될 수 있다.
  - 열 때 어느 탭이 우리 탭인지 확신하지 못하면 표시를 적지 않고 「표시 안 한 탭」으로 등록한다. 이 탭은 처음 열린 자리에 처음 연 주소 그대로 표시 없는 탭이 있으면 끝낼 때 닫는다. 그 자리에 사용자가 같은 주소의 탭을 열어 두었다면 그 탭이 닫히고 그 탭에서 `runJs` 가 돌 수도 있다.
- 우리 탭이 닫히지 않고 남는 경우: 다른 사이트로 늦게 넘어가 표시가 지워졌을 때와 10분이 넘게 손대지 않다가 새 문서로 바뀌었을 때가 있다. 우리 탭이 이동하는 순간 사용자가 같은 창에서 탭을 열고 닫은 경우도 마찬가지다. 사용자 탭일 수 있어 표시를 다시 적지 않고 놓아 둔다. 탭이 60개를 넘거나 읽을 수 없는 탭이 있어 다 훑지 못했을 때도 남을 수 있다. 끝낼 때 훑기는 5초 안에 마친다. 남은 탭은 직접 닫는다.
- 우리 탭을 놓치면 로그에 「우리 탭 N개를 못 찾았어요(이미 닫혔을 수 있어요)」 한 줄이 남는다. 놓친 탭을 쓰려고 하면 「놓쳤어요」 오류가 난다. 그때는 `openTab` 으로 다시 열거나 `listBrowserTabs()` 로 찾아 `attachBrowserTab()` 으로 붙인다.
- AI 창 크기와 `innerWidth` 는 사파리 창 최소 폭(약 336px)과 화면 크기에 묶인다.

## 사파리 앱(시험판)

사파리 옆에 붙어 클로드 · 제미나이 · ChatGPT 에게 묻는 옆 창 앱이 `app/` 에 있다(이 맥에서만 도는 시험판, ⌥⇧S). 빌드 · 쓰는 법 · 맥 허락 창 · 한계는 [`app/README.md`](app/README.md).

## 개발

```sh
npm test                                   # 단위 시험(사파리 없이)
SAFARI_IT=1 npx vitest run test/integration/tabs.it.test.ts   # 통합 시험(진짜 사파리, 파일 하나씩)
```

`src/` 를 고치면 `npm run build` 로 `plugin/server.mjs` 도 다시 만들어 함께 커밋한다(플러그인은 설치할 때 빌드하지 않는다).

측정은 `npm run build && node dist/scripts/bench.js`(진짜 사파리를 쓴다. 자기가 연 탭 · AI 창만 열고 끝에 닫는다).

통합 시험은 자기가 연 탭에만 표시를 달아 열고 닫으며 사용자 탭은 건드리지 않는다. `spikes/` 에는 `.mcpb` 안에서 osascript 가 도는지 · 사파리 창 최소 폭을 재 보는 첫 시험이 들어 있다.

## 새 버전 내기(관리자용)

1. `src/version.ts` 의 `VERSION` 을 올리고, `test/unit/version-sync.test.ts` 가 확인하는 자리를 모두 같은 값으로 맞춘다: `package.json` · `package-lock.json`(루트 두 곳) · `plugin/.claude-plugin/plugin.json` · `.claude-plugin/marketplace.json` · `mcpb/manifest.json` · `Formula/safari-attraction.rb`(`tag: "vX.Y.Z"`).
2. `npm test` 로 버전 맞춤 시험을 포함한 단위 시험을 통과시킨다.
3. `npm run build` (`plugin/server.mjs` 갱신) → `npm run pack:mcpb` (`out-mcpb/safari-attraction-X.Y.Z.mcpb` 생성).
4. `npm run check:bundle` 로 커밋한 `plugin/server.mjs` · `plugin/jxa/host.js` 가 지금 `src/` 에서 다시 만든 것과 같은지 확인한다(다르면 3번을 다시 한다).
5. 커밋 → 태그 `vX.Y.Z` → `main` 과 태그 push.
6. GitHub 릴리스를 만들고 `.mcpb` 파일을 붙인다.
